# Provider compatibility

Paths and versions below were **verified from official documentation on 2026-11-25**. Provider conventions change: **verify before use** in your installed version and organization.

## Skill standard

Both Claude Code and Codex follow the [agentskills.io](https://agentskills.io/) open standard for skills as portable instruction folders with `SKILL.md`. AE canonical skills live at `framework/skills/<slug>/SKILL.md`; provider copies are generated by `ae skills install` with a manifest, SHA-256 checksums, and pinned version. Do not hand-edit generated files.

## Claude Code

| Scope | Documented path |
| --- | --- |
| User (all projects) | `~/.claude/skills/<slug>/SKILL.md` |
| Project | `.claude/skills/<slug>/SKILL.md` |
| Plugin | `<plugin>/skills/<slug>/SKILL.md`, with `.claude-plugin/plugin.json` |

Reference: [Claude Code skills documentation](https://docs.claude.com/en/docs/claude-code/skills).

## Codex

| Scope | Documented path |
| --- | --- |
| User | `$HOME/.agents/skills/<slug>/SKILL.md` |
| Repo | `$CWD/.agents/skills` or `$REPO_ROOT/.agents/skills` |
| Admin | `/etc/codex/skills` |

Optional metadata: `agents/openai.yaml`.

Reference: [OpenAI Codex skills documentation](https://developers.openai.com/codex/guides/skills).

> **Important:** `.codex/skills` is **not** a documented Codex skill path. Do not install to it or claim compatibility with it. Use `.agents/skills` as documented.

## Verification checklist

- [ ] Confirm the provider version and its current documented skill directory.
- [ ] Run `ae skills install --provider <name> --scope <scope> --version <v> --dry-run` first.
- [ ] Check the manifest and SHA-256 checksums after installation.
- [ ] Confirm no unrelated files are overwritten in the target path.
- [ ] Reinstall skills after upgrading the catalogue version.
- [ ] For plugin bundles, run `ae skills export --out dist/plugins` and validate with the provider CLI before enabling.

## Status

`ae skills install`, `uninstall`, and `export` are implemented locally: installs materialize documented paths with manifests and checksums; exports create Claude/Codex plugin bundle directories without publishing them. `ae chat --provider fake` is implemented and exercised offline. Claude Code and Codex CLI chat adapters are implemented locally with opt-in `--confirm-live`, managed worktrees, and local stub argument tests, but live model invocation was **not exercised**. `run`, `resume`, and `autopilot` add opt-in `--allow-writes`: Claude switches from `Read` to `Read,Write,Edit` without shell tools and passes temporary permission settings that block file-tool reads and writes outside the working directory (requires Claude Code v2.1.314 or later; older binaries are rejected), while Codex switches from `read-only` to `workspace-write`. These write modes were stub-tested only, not exercised with live providers. Provider name is recorded in task evidence; model is recorded only when an adapter reports it. Usage is stored as `known: false` when not reported, never as zero. `ae verify` records real local command results; live model invocation was not exercised.
